# ESP32 Project Initialization

Use this skill when the user wants to start a new ESP-IDF project. Follow the ordered workflow below. Do not skip pre-work.

## Workflow

### Phase 1: Board Pre-work

1. Ask the user for:
   - Chip variant (e.g. esp32, esp32s3, esp32c6)
   - Module type (WROOM / WROVER)
   - Board model name (e.g. CYD / ESP32-2432S028R, ESP32-DevKitC, M5Stack Core2)
2. Fetch canonical pinout from a known source:
   - vendor GitHub repo (e.g. witnessmenow/ESP32-Cheap-Yellow-Display/PINS.md)
   - Espressif docs
   - manufacturer schematic PDF
3. Populate a structured board definition using the BMGR YAML format:
   - `components/<board_name>/board_info.yaml` — metadata (board name, chip, version, manufacturer)
   - `components/<board_name>/board_peripherals.yaml` — low-level bus/gpio/peripheral pin assignments (I2C, SPI, UART, LEDC, GPIO)
   - `components/<board_name>/board_devices.yaml` — functional devices that depend on peripherals (LCD, touch, audio codec, sensors), with I2C addresses, SPI modes, init params
4. **STOP. Present the proposed pinout to the user. Get explicit agreement before proceeding.**

### Phase 2: Hardware Verification

1. Ask the user to connect the board via USB and identify the serial port (`/dev/ttyUSB0`, `/dev/ttyACM0`, COM3, etc.)
2. Run `idf.py -p <port> monitor` briefly to confirm the device responds (boot log visible, no error)
3. Exit monitor (`Ctrl+]`)
4. Only proceed if hardware connection is confirmed. If no device found, stop.

### Phase 3: Project Creation

1. `idf.py create-project --cpp <project_name>` — creates C++ project with `.cpp` entry point
2. `idf.py set-target <chip>` — e.g. esp32, esp32s3, esp32c6
3. Set up Python virtual environment for test tooling (runs on host, not on device):
   - `uv init --no-project` — creates `pyproject.toml` without a project type (not a library/app, just tooling)
   - `uv add --dev pytest-embedded[serial]` — adds test framework as dev dependency
   - This keeps Python deps isolated per project, neither system-wide nor IDF-global
4. Install BMGR board component if using one:
   - For community boards: add to `main/idf_component.yml`:
     ```yaml
     dependencies:
       espressif/esp_friends_boards: "^0.5.0"
     ```
   - For custom board: ensure `components/<board_name>/` YAMLs exist from Phase 1
4. Run `idf.py bmgr -b <board_name>` — generates init code under `components/gen_bmgr_codes/`
5. `idf.py menuconfig` — configure:
   - Partition table (factory vs OTA)
   - Flash size / mode
   - WiFi / Bluetooth if needed
   - Component-specific Kconfig options
6. `idf.py save-defconfig` — creates `sdkconfig.defaults`
7. `idf.py build` — verify compilation succeeds

### Phase 4: Flash and Verify

1. `idf.py -p <port> flash`
2. `idf.py -p <port> monitor` — confirm app runs on device

## Generated Project Structure

```
<project_name>/
├── CMakeLists.txt              # project-level build config
├── main/
│   ├── CMakeLists.txt          # main component registration
│   └── <project_name>.cpp      # app_main() entry point
├── components/
│   ├── <board_name>/           # board definition (Phase 1)
│   │   ├── board_info.yaml
│   │   ├── board_peripherals.yaml
│   │   ├── board_devices.yaml
│   │   └── sdkconfig.defaults.board  (optional)
│   └── gen_bmgr_codes/         # auto-generated by bmgr (do not edit)
├── sdkconfig                   # generated by menuconfig (gitignore)
├── sdkconfig.defaults          # project defaults (commit this)
├── build/                      # compiled output (gitignore)
├── pyproject.toml              # uv-managed Python tooling config
├── .venv/                      # virtual env (gitignore)
└── main/idf_component.yml      # component registry dependencies
```

## Key Rules

- **set-target before menuconfig** — changing target later wipes sdkconfig
- Board YAMLs go in `components/<board_name>/`, not in `main/`
- Serial port (`-p /dev/ttyUSB0`) is a CLI arg, not stored in sdkconfig
- Commit `sdkconfig.defaults` and board YAMLs. Gitignore `sdkconfig` and `build/`
- BMGR requires ESP-IDF v5.4.3+. Fall back to manual pin `#define`s + JSON board file if using older IDF.
- If the board is not supported by BMGR (no matching esp_friends_boards entry), write the three YAML files manually from the fetched pinout.
